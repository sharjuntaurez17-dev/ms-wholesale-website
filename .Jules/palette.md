## 2024-05-24 - Login Form and Link Accessibility Improvements
**Learning:** Found that `<label>`s were not properly tied to inputs, and interactive elements ("Forgot password?", "Sign up") were built using `<span>`s with inline styles. Because the components rely heavily on inline styles from `theme.js`, keyboard users cannot access these actions. Converting interactive spans to `<button type="button">` with standard structural tags requires a specific style reset (`background: "none", border: "none", padding: 0, font: "inherit"`) to maintain the UI's strict visual appearance while enabling accessibility.
**Action:** Always verify `htmlFor` and `id` pairing on forms, and actively convert inline-styled `<span>` buttons to semantic `<button type="button">` using the style reset approach when working within this design system.
