## 2024-08-10 - Form Accessibility and Semantic Elements
**Learning:** The application heavily relies on inline styles and non-semantic elements (like `<span>` with `cursor: "pointer"`) for interactive components, and input structural associations (like `htmlFor` and `id`) are sometimes missing. Dynamic error messages also lacked screen reader support.
**Action:** Always convert interactive `<span>` elements to native `<button type="button">` elements using the CSS style reset `background: "none", border: "none", padding: 0, font: "inherit"` to maintain visual appearance while enabling keyboard accessibility. Ensure `<label>` elements are paired with `<input>` elements using `htmlFor` and `id`. Add `role="alert"` and `aria-live="polite"` to dynamic error message containers.
