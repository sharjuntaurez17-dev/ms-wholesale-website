## 2024-05-14 - Semantic HTML Over Interactive Spans
**Learning:** The application's heavy reliance on inline styles occasionally causes interactive elements (like text links for "Forgot password" or "Sign up") to be incorrectly implemented as `<span>` tags. This creates significant accessibility barriers, as these elements completely fail keyboard navigation and are not properly announced as interactive by screen readers.
**Action:** When finding `<span>` or `<div>` tags acting as buttons or links, always convert them to native semantic elements like `<button type="button">` or `<a>`. Use reset inline styles (`background: "none", border: "none", padding: 0`, and inheriting font properties) to maintain the existing visual design seamlessly while providing built-in accessibility.
