## 2024-10-20 - Explicit Form Accessibility Associations and Dynamic Errors
**Learning:** In React applications utilizing native HTML5 input fields and custom error validation, explicit `htmlFor`/`id` associations must be added to custom form fields. Also, when dynamic inline validation errors appear conditionally, the error container must have `role="alert"` and `aria-live="polite"` so screen readers properly announce the error conditionally to the user. Using `noValidate` on forms is required if relying on React state to handle validation display for empty required fields, otherwise native HTML validation bubbles prevent custom JS `onSubmit` handlers from triggering.
**Action:** Consistently explicitly link `<label>` and `<input>` using matching `htmlFor` and `id`, rather than just visual proximity, and always append `role="alert"` and `aria-live="polite"` to dynamically appearing error text.
