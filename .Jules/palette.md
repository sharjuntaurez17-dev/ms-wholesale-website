## 2024-03-08 - Accessible Forms and Semantic Interactions
**Learning:** Found interactive elements ("Forgot password?" and "Sign up") implemented as generic `<span>` tags, breaking keyboard accessibility (tab navigation) and missing screen reader semantics. Additionally, React validation logic requires empty inputs to bypass native HTML5 `required` constraints if testing with Playwright, handled via `noValidate` on the `<form>`.
**Action:** When working on this application, always convert interactive `<span>` or `<div>` elements into semantic `<button type="button">` using the CSS reset pattern `background: "none", border: "none", padding: 0, font: "inherit"` to ensure proper a11y focus states while preserving exact visual appearance. Pair `<label>` and `<input>` with `htmlFor` and `id`, and add `aria-live="polite"` to dynamic error states.
