## 2024-09-19 - Accessibility Improvements for Splitwork Login Screen
**Learning:** React applications utilizing extensive inline styles and custom components often inadvertently substitute semantic HTML elements (like `<button>`) with generic elements (like `<span>`), leading to critical keyboard and screen reader accessibility gaps. Additionally, dynamic form errors typically lack ARIA live region announcements.
**Action:** When auditing such components, actively seek out clickable `<span>` or `<div>` elements and replace them with semantic `<button type="button">` or `<a>` elements, applying CSS reset styles (`background: "none", border: "none", padding: 0, font: "inherit"`) to preserve visual design while restoring accessibility. Always add `role="alert"` and `aria-live="polite"` to conditional error message containers.
