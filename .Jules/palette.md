## 2023-10-27 - Forms and Interactive Spans Accessibility
**Learning:** The application heavily utilizes inline styles, which has led to interactive elements (like 'Forgot password' and 'Sign up' links) being implemented as `<span>` tags, making them completely inaccessible to keyboard users. Additionally, custom form structures often lack explicit label bindings (`htmlFor`/`id`), and conditional error messages are rendered without `aria-live` attributes.
**Action:** When working on this application's components, systematically convert interactive spans to native `<button type="button">` elements using a CSS reset (`background: "none", border: "none", padding: 0, font: "inherit"`) to maintain the visual appearance. Always explicitly pair `<label>` and `<input>` tags, and add `role="alert"` with `aria-live="polite"` to dynamically rendered form error containers.
