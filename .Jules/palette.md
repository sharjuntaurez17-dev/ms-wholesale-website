## 2024-07-24 - Accessibility and Semantic HTML Patterns
**Learning:** The application extensively uses non-semantic inline elements (like `<span>` with cursor styling) for interactive buttons such as "Forgot password" and "Sign up" links, missing necessary structural pairings (like missing `htmlFor`/`id` on labels/inputs), and lacks ARIA labels for dynamic containers (such as form error messages). This pattern severely hampers keyboard navigation and screen reader usability on forms.
**Action:** When working on form or navigational components in this app, proactively convert interactive `<span>` tags to `<button type="button">` using the style reset (`background: "none", border: "none", padding: 0, font: "inherit"`) to preserve visual alignment. Also, always check for matching `id` and `htmlFor` on related form fields and ensure error containers have `role="alert"` and `aria-live="polite"`.
