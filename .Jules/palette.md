## 2024-07-04 - Semantic Buttons Over Interactive Spans in Inline Stylings
**Learning:** In codebases heavily reliant on inline CSS (such as this one), developers often use `<span>` or `<div>` elements for interactive items like links ("Sign Up") or actions ("Forgot password?") to avoid default button styling, resulting in a loss of keyboard accessibility (e.g., they fall out of tab order). Additionally, structural links between form labels and inputs are frequently omitted (missing `htmlFor` / `id` pairings).
**Action:** When finding clickable `<span>` elements, always convert them to `<button type="button">` (or `<a>` if navigating) and use the inline style reset `background: "none", border: "none", padding: 0` to preserve the visual appearance while automatically restoring keyboard navigation and a11y focus behavior. Explicitly pair `<label>` and `<input>` elements using matching `htmlFor` and `id` attributes to guarantee screen reader support.
