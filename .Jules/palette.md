## 2025-01-20 - Login Screen Form Accessibility and Interactive Elements
**Learning:** Found a recurring pattern in this app's components where interactive links (like "Forgot password?" and "Sign up") are built using `<span>` tags with `cursor: pointer` inline styles, bypassing native keyboard navigation and screen reader support. Additionally, forms feature visually associated labels that are programmatically detached from their inputs (missing `htmlFor`/`id` linking).
**Action:** When working on UI enhancements, actively convert interactive `<span>` elements into semantic `<button type="button">` or `<a>` elements using the CSS reset pattern (`background: "none", border: "none", padding: 0`) to maintain identical visual styling while unlocking native accessibility. Ensure all form `<label>` elements are explicitly linked to their corresponding `<input>` via matching `htmlFor` and `id` properties.
