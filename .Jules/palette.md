## 2023-10-27 - Form Accessibility in React

**Learning:** When adding native HTML5 `required` attributes to inputs within a React application, if the form uses custom validation logic inside an `onSubmit` handler, the native browser validation will intercept the submission and prevent the React `onSubmit` from firing if the fields are empty. Furthermore, inline styles are sometimes mistakenly applied to interactive elements like `<span>` tags, which are inherently inaccessible via keyboard and lack semantic meaning.

**Action:** To maintain accessibility without breaking custom React form handling, explicitly add the `noValidate` attribute to the `<form>` element. This instructs the browser to ignore its default validation popup, allowing the React `onSubmit` handler to process the submission and render custom, accessible error messages (which must include `role="alert"` and `aria-live="polite"`). Also, convert non-semantic interactive tags (like `<span>`) to semantic `<button type="button">` tags, applying a CSS reset (`background: "none", border: "none", padding: 0, font: "inherit"`) to retain their original visual appearance while granting full keyboard accessibility and screen reader support.
