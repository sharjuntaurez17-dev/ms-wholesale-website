## 2024-11-01 - React Form Accessibility and Interactive Elements Pattern
**Learning:** In the Splitwork application, many inline-styled interactive UI elements like "Forgot password?" and "Sign up" are implemented as `<span>` tags rather than semantic buttons, causing poor keyboard accessibility. Additionally, form field validations lack native accessibility attributes linking `<label>` and `<input>`. Adding `noValidate` to the form allows React state validation to work properly alongside native accessibility enhancements like `required` and `aria-required="true"`.
**Action:** When working on UI components in this app, explicitly pair `<label>` and `<input>` using matching `htmlFor` and `id` properties. Always convert interactive `<span>` or `<div>` elements acting as buttons into semantic `<button type="button">` elements utilizing the CSS reset `background: "none", border: "none", padding: 0, font: "inherit"` to ensure keyboard accessibility without breaking the existing visual design.
