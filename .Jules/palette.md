## 2024-05-18 - Form Accessibility & Semantic Interactive Elements
**Learning:** In Splitwork's LoginScreen, multiple interactive links ("Forgot password?", "Sign up") were built using `<span>` tags with `cursor: "pointer"`, preventing keyboard navigation (tabbing). Additionally, form inputs lacked structural `<label>` associations via `id` and `htmlFor`, and the dynamic error message container was missing ARIA roles to alert screen readers when errors occurred.
**Action:** Always convert interactive `<span>` tags meant to behave as buttons into `<button type="button">` while using a CSS style reset (`background: "none", border: "none", padding: 0, font: "inherit"`) to preserve visual design while enabling keyboard focus. Always link `<label>` and `<input>` elements using matching `htmlFor` and `id` attributes. Always add `role="alert"` and `aria-live="polite"` to dynamically rendered error message containers.
