## 2025-02-20 - Form Accessibility and Semantic Elements
**Learning:** In this application, forms and links were frequently built using structural flaws: inputs were missing programmatic label associations (`id` and `htmlFor`) and interactive text items (like "Forgot password?" and "Sign up") were built using `<span>` tags rather than semantic buttons, causing poor screen reader experiences. In addition, when adding standard HTML validation attributes to allow Playwright testing of custom validation logic, custom React form handlers may be bypassed.
**Action:** Always wrap interactive items in semantic `<button type="button">` with style reset `background: "none", border: "none", padding: 0, font: "inherit"` to match existing styles while adding full keyboard/screen reader access. Add `noValidate` to `<form>` tags when maintaining custom client-side validation logic alongside HTML5 validation attributes (`required`).
